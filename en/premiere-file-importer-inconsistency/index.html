The full guide: what happened, what not to do, the three cases

Premiere: “File importer detected an inconsistency in the file structure”

Premiere Pro shows this for two unrelated problems, and which one you have depends on when it appeared: while importing a clip from a camera, or while exporting. The fixes have nothing in common.

Its sibling message, “The file has an unsupported compression type”, usually points at the same files.

If it appeared on import

Premiere reads the file's index and finds it doesn't match what's in the file. With camera footage that almost always means a recording that was cut off before the camera finished writing it (on Sony bodies the file may end in .RSV instead of .MP4), or a file that came through a transfer that stopped halfway.

Quick test: open the same file in VLC and play the last minute. If VLC fails too, the file is broken and Premiere is only the messenger. If VLC plays it fine, including the end, Premiere's media cache is the likelier culprit: clear it (Preferences → Media Cache → Delete) and import again.

If the file is broken

  1. Don't format the card, don't keep shooting on it. Copy the file to your computer and work on the copy.
  2. A sample clip. A healthy recording from the same camera at exactly the same settings: same resolution, same frame rate, same recording quality. Length doesn't matter. If you don't have one, put a card in, lens cap on, record 30 seconds.
  3. untrunc. A free tool that rebuilds the index from your sample clip (download it here, Windows, with a simple interface). Pick the sample clip, pick the broken file, run it. It's the same method the paid tools use. Sometimes it takes a second run.
  4. Then check the whole file. The duration should match what you shot. Scrub to five or six points across it, especially near the end, and watch a few seconds at each. Lips should still match sound. If anything's off, the answer is a better-matched sample clip and another pass, not a different program.

Import the rebuilt file, not the original, and scrub through it in Premiere once more before you cut.

If it appeared on export

Then it isn't about your footage at all. Premiere is failing to write the export file. Adobe's own forum lists the usual causes:

  • The destination folder name has non-English characters (Hebrew, accents, Chinese). Export to a folder whose whole path is plain English letters.
  • The drive ran out of space. Free some up, or export to another drive.
  • Hardware encoding on some versions. Version 23.1 had a known bug, fixed in 23.2. Switch to software encoding or update.

Short answers

  • Premiere shows the error but VLC plays the file. Then the file is most likely fine. Clear Premiere's media cache and import again.
  • It only happens when I export. That's a writing problem, not a footage problem: a folder name with non-English characters, a full drive, or hardware encoding on an affected version.
  • What about “The file has an unsupported compression type”? Premiere shows it for the same broken files, when it can't find a readable index at all. Treat it the same way: test in VLC, then rebuild.
